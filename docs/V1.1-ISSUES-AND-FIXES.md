## Details

### 1. No ALBs after `terraform apply`
- 🔎 Terraform only creates the ALB controller's IAM role. ALBs are created by the in-cluster controller reacting to Ingress objects that Argo CD syncs.
- ✅ Expected behaviour; ALBs appear once Argo syncs the apps.

### 2. ALB controller webhook x509 "unknown authority"
- 🔎 The controller's webhook cert was not yet trusted when other installs created Services.
- ✅ Restart the controller; script 01 re-run succeeds. CI skips ALB on kind (`SKIP_ALB_CONTROLLER=1`) so this race is not covered by CI.

### 3. CI could not assume the AWS role
- 🔎 GitHub OIDC `sub` must match the trust policy exactly; subjects are immutable once issued.
- ✅ Added GitHub OIDC provider and plan/apply roles in Terraform (`modules/iam/github_oidc.tf`); the apply job uses `environment: dev` and needs manual approval in the GitHub UI. PRs #9–#14.

### 4. EKS access denied for SSO user
- 🔎 The access entry needs the **full** SSO role ARN, including the `/aws-reserved/sso.amazonaws.com/...` path.
- ✅ Used the full ARN. See open item 17.

### 5. Local apply flips `cluster_creator`
- 🔎 A local apply as a different principal changes the cluster_creator entry.
- ✅ Prefer applying through CI.

### 6. Script 01 prompts consumed by piped `Y`
- 🔎 `echo Y |` only answers the first prompt; the rest read EOF.
- ✅ Preset every env var (prompts are skipped when set). Same pattern used in CI.

### 7. Argo CD helm install hit ALB webhook race
- ✅ Re-run succeeded.

### 8. GitHub App created on the wrong owner
- 🔎 A personal-account app cannot be installed on the org.
- ✅ Recreated under org your-org: `mackllc-argocd-gitops-readers`, Contents read-only, installed on the gitops repo only. Old personal app  to be deleted.

### 9. Script 02 bugs
- 🔎 Leftover `GITHUB_USERNAME` reference from the PAT design; mangled masked-secret line.
- ✅ Secret now uses `githubAppID`, `githubAppInstallationID`, `githubAppPrivateKey`.

### 10–13. CI for scripts
- Added `.github/workflows/scripts-test.yml`: static → bootstrap smoke (kind, 01–03) → app layer (kind, 04–06 with a fake `gh`).
- Script 03 now accepts `RDS_MASTER_SECRET_ARN` instead of always calling `terraform output`.
- Scripts 04/05 accept `POLL_INTERVAL`, `MAX_WAIT`, `TRIGGER_DELAY` overrides.
- Smoke assertion fixed (`kubectl get secret NAME`, not NAME + selector).
- Ruleset "Protect scripts branch" requires PRs and the three checks.
- Open: PR pushes did not auto-trigger the workflow (cause undiagnosed).

### 14. IRSA trust subject format (found on first real run of script 03)
- ❌ ESO `ClusterSecretStore` stuck `InvalidProviderConfig`; logs: `AssumeRoleWithWebIdentity 403 AccessDenied`.
- 🔎 `modules/irsa-role/main.tf` built `system:serviceaccount:external-secrets/external-secrets` (slash). The token's real `sub` is `system:serviceaccount:external-secrets:external-secrets` (colon). Verified by decoding a token from `kubectl create token --audience sts.amazonaws.com`. Affects every role built from the module (ESO, ALB controller, per-service roles).
- ✅ Fixed: subject now uses `replace(sa, "/", ":")` (PR #17, applied). ESO syncs.
- Cluster note: the live ClusterSecretStore `auth` block was removed while debugging and must be restored (re-run script 03).
- Lesson: CI on kind can't catch IAM trust bugs; the first real-cluster run is the test for IRSA.

### 15. Trivy gate blocked all builds
- ❌ 8 of 8 backend builds failed at Trivy (`exit-code 1`, HIGH/CRITICAL). 90 fixable findings in qc-service alone (logback, spring-web, tomcat-embed).
- ✅ Gate set to `exit-code 0` (backend PR #3, frontend PR #3). Findings go to code scanning + one GitHub issue per service (assigned to Copilot) + Dependabot (maven, npm, docker, actions).
- ⚠️ TODO: set `exit-code` back to `1` before go-live once findings are fixed.

### 16. Reporting steps broke the build
- ❌ Forked backend repo had Issues disabled; issue step failed the job.
- ✅ Enabled Issues; SARIF/issue steps are `continue-on-error` (PR #11).
- ⚠️ TODO: issue titles truncated ("in -service"); Copilot assignee not applied.

### 17. GitOps App token missing
- ❌ `GITOPS_APP_ID` / `GITOPS_APP_PRIVATE_KEY` not set; reader App has no permissions. New writer App `mackllc-ci-gitops-writer`  created, but its permission fields were greyed out in the UI (cause undiagnosed).
- ⚠️ **Known gap (stopgap):** deploy steps use static `secrets.GITOPS_TOKEN` (backend PR #17, frontend PR #3). Violates the no-static-credentials design. The frontend token also lacks write access (403), so mackllc-ui tag was bumped by hand (gitops PR #3).
- ✅ Fix: App UI kept creating Apps with empty permissions; the **manifest flow** created `mackllc-ci-gitops-writer-3`  with contents+PR write, metadata read. `GITOPS_APP_ID` / `GITOPS_APP_PRIVATE_KEY` stored in backend and frontend (dev environment + repo level for promote workflows). Workflows mint a per-run token with `actions/create-github-app-token` scoped to `gitops` (backend PR #21, frontend PR #4).
- ⏳ After the first passing build: delete `GITOPS_TOKEN`, remove old empty-permission Apps  and local `.pem` files.

### 18. Concurrent gitops push race
- ❌ `cannot lock ref 'refs/heads/main'` when 8 services deploy at once; and a re-run can't repush an immutable ECR tag.
- ✅ Pull --rebase retry loop (backend PR #18). All 8 builds then green.

### 19. `<ACCOUNT_ID>` placeholders in gitops values
- ✅ Replaced with the real account ID (gitops PR #2).

### 20. First deploy (script 05/06)
- ✅ 9 Argo apps created; all Synced/Healthy; 9 pods Running; UI ALB returns HTTP 200.
- Script 06 false failures fixed (reads ExternalSecret READY column; probes real routes, accepts 401/403/405) in PR #20.
- api-gateway Ingress had no ALB address because of the missing `SetRulePriorities` permission (fixed, PR #19). Argo CD ingress still has none.
